# Frontend menu behavior requirements

Status: source-derived baseline for later implementation; 2026-10-18. Applies only to USA `SLUS_200.56`, SHA256 `EFC55119F17E35F6AEE95335499F5845D5FAD4274434E803449C6E14CBFA73AB`.

This document describes the original frontend, rather than treating the current native placeholders as specifications. “Source-confirmed” below means observed in the executable's recovered functions, instructions or data. It does not mean the original behavior was replayed in PCSX2. Requirements are candidates for reconstruction; uncertainties and chosen host adaptations are identified explicitly.

## Evidence and reproduction

- Direct Ghidra 12.1.4 / Emotion Engine exports: [analysis/menus](../../../analysis/menus), generated by [ExportMenuRequirements.java](../../../scripts/ghidra/ExportMenuRequirements.java). `index.tsv` covers **440 functions** with addresses and direct calls; matching C and address-bearing assembly files preserve the behavior.
- [strings.tsv](../../../analysis/menus/strings.tsv), generated by [ExportMenuStrings.java](../../../scripts/ghidra/ExportMenuStrings.java), connects function, localization-table address, English pointer and text. These are the English table entries; other languages must not reuse guessed English widths.
- [tables.json](../../../analysis/menus/tables.json), generated by [export-menu-tables.ps1](../../../scripts/export-menu-tables.ps1), inventories the 19 music entries, 24 movie entries and 16 cheat rewards below. The extractor verifies the release hash before using fixed virtual-address mappings.
- Main menu IDs are established by construction in `ShMSetupState::enter`, **0x00194A80**. Common input dispatch is `update`, **0x001962E0**; deferred menu change is `changeMenu`, **0x00197668**.
- Presentation evidence and reference hashes remain in [RGBA texture analysis](../../../docs/rgba-textures.md) and [asset-use audit](../../../docs/intro-property-audit.md). A preview of an asset alone does not specify its game blend, tint, geometry or timing.

Re-export the two Ghidra scripts against `analysis/startup/StartupTrace` using the recorded headless Java/EE environment, `-process SLUS_200.56 -noanalysis`, with output `analysis/menus`. Rebuild table data with `scripts/export-menu-tables.ps1`; preserve generated evidence rather than editing it into a proposed requirement.

## Original hierarchy and screen identities

```text
Profile [7] → Main [0]
  OPERATIONS → MISSION SELECT [1] → mission briefing/loadout [5] → level intro/game
  TWO - PLAYER → TWO PLAYER mission selection [2] → level intro/game
  SYSTEM OPTIONS [3]
    SETTINGS [6]
    CONTROLLER [13]
      PLAYER 1 → CONTROLLER 1 OPTIONS [8]
      PLAYER 2 → CONTROLLER 2 OPTIONS [14]
    EXTRAS [9]
      MUSIC PLAYER [10]
      MOVIE PLAYER [11]
      CHEAT GRID [12]
  DOSSIER [4] — mission/time/objective progress table
```

`ShMenu1::getNextMenu` (0x0016F8C8), `ShMenu3::getNextMenu` (0x00175430), `ShMenu9::getNextMenu` (0x00183348), and `ShMenu13::getNextMenu` (0x001874C0) establish the branches. Root Two Player routing is conditional on a connected second controller (0x0016B0A0).

| --- | --- | --- | --- |
| 0 / ShMenu0 | OPERATIONS; TWO - PLAYER; SYSTEM OPTIONS; DOSSIER | Profile 7 | Cross invokes accept feedback, then routes to 1/2/3/4. Two Player remains at 0 when the controller-state check fails. |
| 1 / ShMenu1 | Mission selector, level IDs 1..14, with mission status and rendezvous information | Main 0 | Only an open mission advances to briefing/loadout 5. Cross sets the next level and mode defaults, plays accept, and arms timing fields. A locked mission is denied without calling its launch handler. |
| 2 / ShMenu2 | Two-player mission selection and status | Main 0 | Cross checks two-player eligibility, sets next level and two-player mode, requests game-state transition/flush, and plays accept; deny if locked. This screen is not a pair of profile-selection buttons. |
| 3 / ShMenu3 | SETTINGS; CONTROLLER; EXTRAS, in that order | Main 0 | Cross → 6 / 13 / 9. |

| 5 / ShMenu5 | OBJECTIVES; WEAPONS; ENEMIES tabs plus START action | Mission Select 1 | Cross requests the selected level/game-state transition. Square acts on the active tab; details below. |
| 6 / ShMenu6 | Sound mode; FX volume; Music volume; Voice volume; Vibration | System Options 3 | Left/right adjust the current control live; Cross commits values, conditionally saves and returns; Triangle restores entry audio state before returning. |

| 9 / ShMenu9 | MUSIC PLAYER; MOVIE PLAYER; CHEAT GRID | System Options 3 | Cross → 10 / 11 / 12. |
| 10 / ShMenu10 | Circular track list; layout selection | Extras 9 | Left/right choose track; Cross calls PlayMusic for its asset; Square cycles five visual layouts. |
| 11 / ShMenu11 | Movie list with availability state | Extras 9 | Cross starts the selected available movie through a transition state; Back acts only in the appropriate list state. |

Back destinations above use the callback and common dispatcher together. For example, configuration screen `getNextMenu` stubs are not acceptance routes: their `x` handlers explicitly call `changeMenu(getPrevMenu())`. Profile's `getPrevMenu()==1` must not be interpreted as its Back behavior; profile Back is handled specially.

## Selection commands and state details

### Profile / name creation / deletion

**PRO-01** Display exactly three records; a populated record shows its actual name, mission/progress and formatted objectives. The table reader uses name x=87, level x=287, objectives x=467 with a `%3d` field, and text y=311−35×row. Native placeholder progress “MISSION 1 / 0” is not the final data requirement.

**PRO-02** Existing-row Cross selects the record as the current profile, restores sound variables, and requests Main 0; card/save flags depend on availability and dirty state. Evidence: `x__13ShMenuMemPack` **0x00189098**.

**PRO-03** Empty-row Cross enters a keyboard substate, creates/resets `ShKeyBoard`, and initializes the new profile fields. Subsequent Cross selects a keyboard character, copies the keyboard string, and returns to row selection when keyboard completion is reported. Name-entry cheat strings have an additional original branch. Maximum length, all keyboard keys and duplicate-name handling require a dedicated ShKeyBoard trace; do not infer them from the host text-entry placeholder.

**PRO-04** Triangle during naming cancels and returns to row selection, clearing the provisional name. Ordinary profile-list Triangle requests the frontend's Back transition (to the pseudo-intro/start flow). Evidence: **0x00188D18**, state update **0x001962E0**.

**PRO-05** Square only initiates deletion for a populated row in list state; it opens a Yes/No substate. Cross on No cancels; Cross on Yes invokes `deleteProfile` and returns to the list. Up/Down toggle the confirmation choice in that substate. Evidence: `box` **0x00188C58**, `x` **0x00189098**, `up` **0x00189570**.

**PRO-06** Dirty save confirmation and card-dependent save operations are separate substates in the original. They must not be flattened into unconditional destructive writes.

### Operations, mission briefing and two player

**OPS-01** Operations opens Mission Select directly. Mission IDs cycle through **1..14**, wrapping at both ends. “RENDEZVOUS” is drawn by Mission Select's status panel; source routing does not establish it as an extra submenu item. Evidence: `getNextMenu` **0x0016F8C8**, Up **0x0016F8F8**, Down **0x0016F988**, `drawStatus` **0x0016E6C0**.

**OPS-02** Open-mission rules include the all-levels override, always-open first mission, required objective count, and preceding mission completion. Preserve the exact predicate before enabling launch. Evidence: `isLevelOpen` **0x0016F860**. Cross on an open item sets `setNextLevel`, initializes game mode if zero, plays accept and advances to screen 5; denial must not mutate the next level.

**OPS-03** Screen 5's actual tab labels are **OBJECTIVES / WEAPONS / ENEMIES** (constructor **0x00180AB0**, string references **0x003FB1E8 / 0x003FCBF8 / 0x003FCC00**). Left/right change tabs, with restrictions for mission IDs 1 and 7. Up/Down on the weapons tab cycle weapon presentation. Square there calls `transitionCar`; Square on the enemies tab advances to an available enemy presentation. Cross is the launch action. Evidence: **0x00180768**, **0x00180698**, **0x001807C8**, **0x00180868**, **0x00180988**. Exact car/enemy/weapon catalogues and complete button legend require later scene-level work.

**TWO-01** Root Two Player first checks controller state; its mission screen also enforces `openForTwoPlayer` unless the global unlock override applies. The predicate includes objective thresholds and recorded objective flags. Evidence: **0x0016B0A0**, **0x00174400**.

**TWO-02** Allowed Cross writes next level, game state field +0x34=2, the appropriate two-player mode value where applicable, requests frontend change-state/flush and plays accept. Evidence: **0x00174938**. Decode the raw mode value `0xF00` against original enums before exposing a semantic mode name.

### System Options, settings and controller configuration

**SYS-01** The original System Options list has exactly **SETTINGS, CONTROLLER, EXTRAS**, routed to **6, 13, 9**. Evidence: constructor **0x00175488**, routing **0x00175430**.

**SET-01** Settings selection indices are 0 sound mode, 1 FX volume, 2 music volume, 3 voice volume, 4 vibration. Left/right call the corresponding slider decrement/increment and apply audio values live. Voice adjustment also auditions speech. Evidence: **0x00181650 / 0x00181800**, slider creation **0x00181F98**. Exact slider display labels, step sizes and sound-mode enum names need the slider-class trace.

**SET-02** Enter snapshots audio state. Triangle restores music/FX/voice/mode from that snapshot. Cross accepts vibration and current audio state, conditionally calls `saveIt` when a card is available, and returns to System Options. Evidence: enter **0x00180F50**, Triangle **0x00181380**, Cross **0x00181410**.

**CTL-01** Controller opens **PLAYER 1 / PLAYER 2**, not a settings scheme list directly. These route to 8/14. Both offer **STANDARD / REVERSED / FLIPPED**; their left/right handlers delegate to the same wrapping selection callbacks as Up/Down. Evidence: **0x00187790**, **0x001874C0**, **0x00182A80**, **0x00188208**.

**CTL-02** Cross writes scheme index 0/1/2 into the corresponding current-profile field (+0x37C or +0x380), conditionally saves and returns to Controller 13. Triangle backs without committing a new scheme. Evidence: **0x00182858 / 0x00187FE0**.

**CTL-03** Player 2's update detects disconnection and requests a return. Do not leave the player trapped on an input screen owned by a disconnected pad. Evidence: `update__8ShMenu14` **0x00187A30**.

### Extras, media, cheat grid and dossier

**EXT-01** Extras belongs to System Options. Its choices are **MUSIC PLAYER / MOVIE PLAYER / CHEAT GRID**, routed to 10/11/12. Evidence: **0x001833A0 / 0x00183348**.

**MUS-01** Left/right wrap through the 19 table entries below. Cross calls `ShAudio::PlayMusic` with the selected archive path. Square cycles five visual layouts (indices 0..4). Evidence: **0x00183D30**, **0x00183608**, **0x00183CC8**, **0x00183C10**. Track playback inherits the original audio service's settings; raw SH Viewer audition does not specify the game mix.

**MOV-01** Enter checks locks and selects item zero. Left/right cycle entries when not in the playback transition state. Available and unavailable entries use different text states. Cross only starts playback when the current entry's availability field is nonzero. Evidence: **0x00184AC0**, **0x001847E0**, **0x001851A8**, **0x00185120**.

**MOV-02** Playback pauses the menu IPU background, resolves the selected filename for host/disc access, calls `PlayMpeg` with mask `0x80`, then unpauses the background. Evidence: **0x001846E8**. Preserve return-to-menu behavior and restrict Back during intermediate playback states. The Cross handler arms a 0.3 transition parameter; frame-exact timing and skip parity require runtime verification.

**CHT-01** Build rewards from the 16-entry original table. Mission rewards require all objectives and a recorded completion time strictly below the configured threshold, unless the global override is active. Evidence: **0x001855B0** and table **0x00367B90**. Additional finish-game/all-objectives rewards have separate predicates; their full checks must be ported from the remaining cheat-grid helpers.

**CHT-02** Distinguish unlocked movie rewards from toggleable gameplay/view rewards. Cross applies eligible switches only when the current selection is valid and returns to Extras; unavailable cells cannot apply cheats. `applyCheats` switches on reward keys rather than row order. Evidence: **0x001859C0 / 0x001862A8**. Do not invent gameplay meanings for raw globals until their consumers are traced.

**DOS-01** Dossier displays mission name, time (formatted minutes:seconds) and objective progress from the active profile. Navigation and selection callbacks are no-ops; Triangle returns to Main. Evidence: draw **0x00175D50** and callbacks **0x00176B28..0x00176B70**. It has no source-established “EXTRAS” or “MISSION DATA” child choices.

## Selector and presentation requirements

**UI-01** Standard buttons use SYSTEM.PCK `menu_lightbar_1pc.rgba` with the original selected-button/text colors, as recovered at **0x0019AF08**. Preserve baked alpha, rounded border and gradient. Per-screen geometry belongs to game presentation; the decoder and drawing operation are shared services.

**UI-02** Profile rows use the separate MENU.PCK **menu_lightbar_1pc_long.rgba**. Constructor **0x0018AD90** sets size **640×32**; drawSelect **0x00189E20** computes position **(-6,115+35×row)** from the initialized table origin x=87 and row step 35. Its tint is `mColorLightBlue`, not the standard button-on tint. Selected row text is black. Table text uses y=311−35×row, so a selector-only change must also preserve those original anchors.

**UI-03** Concrete menu constructors override the generic ShButton bounds. System Options, Extras and controller configuration have different positions/sizes; their native selector bounds/text anchors now follow those recovered constructors. Other host placeholder branches fit the actual lightbar's measured alpha-content bounds around their labels until the original screens are rebuilt; this remains an approximation, not pixel parity.

**UI-04** Main uses `TWO - PLAYER`; the two-player screen title uses `TWO PLAYER`. Preserve localization literals instead of normalizing both to one string.

**UI-05** Keep source-origin transforms explicit: sprite y is top-origin in the native mapping, while the text renderer accepts a bottom-origin baseline. Black footer, icon placement and font/color fidelity stay governed by the linked asset audit.

## Native adaptation and known implementation differences

The current reconstruction intentionally uses local profile persistence instead of PS2 memory-card services. Card formatting/emulation/save import is outside the approved slice. Original conditional save calls are evidence for when settings/profile commits happen; they do not require emulating the card.

Current placeholders differ materially from this baseline:
- Operations presently contains artificial MISSION SELECT / RENDEZVOUS child rows.
- Extras is presently under Dossier; original Extras is under System Options.
- Dossier presently has artificial EXTRAS / MISSION DATA choices; original is a progress table.
- Native Two Player contains player rows; original is a mission/status selector.
- Native Controller labels currently say CONTROLLER 1/2 OPTIONS instead of original PLAYER 1/2.
- Settings/media/cheat/gameplay commands remain placeholders. Host name entry is not the original on-screen keyboard.

These are a requirements backlog, not a claim that this documentation pass implemented their behavior. Correcting this hierarchy should be a subsequent reviewed implementation slice.

## Acceptance scenarios for later implementation

1. From each of the three populated/empty profile rows, exercise select, create-name completion/cancel, delete Yes/No, and Back without corrupting another profile.
2. Traverse Main → System Options → Extras → each media/cheat screen, then return by Triangle to its documented parent; Dossier must not expose Extras.
3. Exercise Main Up/Down wrap, both stick and D-pad repeat, plus screen-specific horizontal/configuration controls.
4. Select root Two Player with and without a second controller; disconnect it on Controller 2 Options and verify recovery.
5. Try locked/open missions and locked/available movies: denial must not launch or mutate the next target.
6. Enter Settings, change every control, cancel and verify rollback; repeat with accept and verify the committed active-profile values.
7. Select each controller scheme for each player, distinguish accept from cancel, and preserve the selected profile.
8. Play a movie, skip/end it and verify the animated menu resumes. Play every music record and verify the selected asset; cycle all five layouts.
9. Exercise unavailable/available cheat cells and both types of reward; applying a cheat must use its table key, not its row index.
10. Compare selectors with supplied Operations, Two Player and profile references at a normalized 640×448 viewport; preserve source geometry, tint, alpha and text baseline. Child-screen captures are still needed before claiming their visual parity.

## Unresolved evidence and follow-up

- Full on-screen keyboard layout, character/name limit, special cheat-name semantics and save-error recovery.
- Exact physical enums/vtable slot map for every shoulder/secondary button, plus frame-accurate repeat/transition behavior.
- Exact settings slider increments/mode labels; cheat-grid directional rules/complete availability predicates; detailed two-player eligibility flags.
- Mission/loadout asset catalogue, complete controller diagrams, media teardown/mix/skip behavior and GS blend/mask semantics.
- Source defaults are not proof of all runtime overrides. No emulator navigation session was performed during this static audit.
